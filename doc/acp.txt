1. INTRODUCTION                                             *acp-introduction*

acp.nvim runs AI coding agents in parallel threads, similar to Zed's agent
panel. It is built on the Agent Client Protocol (ACP,
https://agentclientprotocol.com), so it works with any ACP agent. Claude
Code, Codex, and Gemini CLI are configured out of the box; any other ACP
agent is one config entry away.

Work is organized into threads. A thread is one conversation with one agent
plus its own workspace: a tab page, a window layout, and optionally a git
worktree. Several agents can work on the same repository at the same time
without interfering with each other or with you.

Each thread's tab has three columns: your editing windows, the agent chat,
and the threads sidebar on the right. The sidebar groups threads by
workspace — the main checkout first, then one section per worktree — and
shows a status per thread: an animated spinner while working, `?` needs
you, `✓` done, `✗` failed. Background threads that need attention also fire a
notification (see |acp-options|), and `require("acp").statusline()` gives
you a summary for your statusline. Inside the transcript, a tool call the
agent has not finished yet spins in place of its tool icon; the icon
returns when the call lands. A thought spins the same way, folded into a
`✱ thinking…` header that settles into `✱ thought for 12s`; <CR> on it
unfolds the reasoning (|acp-options| `ui.show_thinking` turns thoughts off
entirely).

Every plugin window names itself in a small title chip at its top —
`threads`, `chat`, `prompt`, `details` — with the live detail (thread name
and model, send hints, queue) beside it. The statusline is left to the
bottom of the screen (|acp-options| `ui.global_statusline`).

                                                             *acp-context*
The chat winbar carries a context counter, e.g. `◔ 21%`: how full the
model's context window is, straight from the agent (ACP `usage_update`).
The glyph fills as the window does — `○ ◔ ◑ ◕ ●` — so a glance tells you
whether you are near a compaction. It appears once the agent reports a
figure, usually at the end of the first turn, and agents that never report
one simply have no counter.

Threads, layouts, and conversations survive restarts (|acp-options|
`persist`).

2. REQUIREMENTS                                             *acp-requirements*

- Neovim 0.10 or newer
- Node.js (the bundled Claude Code and Codex adapters run via npx)
- git, when using worktrees
- A logged-in Claude Code, Codex, or Gemini CLI

Run |:checkhealth| `acp` after installing.

3. SETUP                                                           *acp-setup*

With lazy.nvim: >lua

  {
    "zenodea/acp.nvim",
    cmd = { "Acp", "AcpNew" },
    opts = {},
  }
<
Or directly: >lua

  require("acp").setup({
    -- your overrides, see |acp-options|
  })
<

4. COMMANDS                                                     *acp-commands*

                                                                        *:Acp*
:Acp            Open the last active thread, or create one if none exist.

                                                                     *:AcpNew*
:AcpNew [name]  Create a thread. Prompts for the agent and the workspace:
                the main checkout, any existing worktree, or a fresh git
                worktree (you pick its name; dir and branch derive from
                it). With [name], skips the name prompt. Pressing `n` in
                the sidebar inside a workspace section skips the workspace
                prompt and uses that section's workspace.

                                                              *:AcpToggleChat*
:AcpToggleChat  Show or hide the chat column (chat + input windows) of the
                current thread tab.

                                                                  *:AcpFollow*
:AcpFollow      Mark the current window as the one the agent's edits are
                revealed in, and turn follow on. Run it again in that
                window to turn follow off. See |acp-follow|.

                                                               *:AcpInterrupt*
:AcpInterrupt   Interrupt the current thread's turn.

5. KEYMAPS                                                       *acp-keymaps*

Global (configurable via the `keymaps` option, set to `false` to disable):

  <leader>cc    Focus the chat input of the current (or last) thread
  <leader>ct    Focus the threads sidebar
  <leader>cs    (visual) Attach the selection to the chat as a context
                chip like `(file.lua 10-24)` — expanded at send time
  <leader>cd    Attach the diagnostic(s) on the current line, with a chip
                pointing at the offending line
  <leader>cf    Follow the agent in this window, see |acp-follow|

Sidebar:

  <CR>          Open the thread under the cursor
  n             New thread; inside a workspace section, the thread is
                created in that section's workspace
  N             New thread in a brand-new git worktree: asks for the
                worktree name, then the thread name, then the agent
  d             Delete the thread under the cursor
  r             Rename the thread under the cursor

Chat input:

  <CR>          Send the message (insert or normal mode)
  <C-j>         Insert a newline
  <C-c>         Interrupt the agent
  <Esc>         Interrupt the agent (normal mode; in insert mode it just
                leaves insert mode as usual)
  <C-p> <C-n>   Prompt history
  gm            Session config picker (mode / model)
  gq            Edit the queued prompts, see |acp-queue|
  gp            Show the plan the agent is working from, see |acp-plan|
  gs            Show the subagents spawned in this thread, see
                |acp-subagents|
  gf            Toggle follow mode (jump to where the agent works)
  /             Agent slash commands (at the start of the input)
  @             Complete project files into whole-file context chips
  y a n         Answer a pending permission prompt (allow / always / deny)

Chat transcript:

  <CR>          Expand or collapse the entry under the cursor. Expanding
                a tool call shows its whole diff, however long; expanding
                a thought shows the reasoning behind its header
  <S-CR>        Open the tool call's full, untruncated content (diffs,
                terminal output) in a float; `q` or `:q` closes it.
                Requires a terminal that distinguishes Shift-Enter from
                Enter (kitty, WezTerm, Ghostty, iTerm2 with CSI u).
  i             Focus the message input
  <C-c> <Esc>   Interrupt the agent
  gd            Jump to the code location of the tool call under the
                cursor (agents report the file/line they touched)
  gm gq gp gs gf
                As in the input window

The transcript cursor only rests on content lines; blank separator lines
are skipped in the direction of movement.

6. THE PROMPT QUEUE                                                *acp-queue*

Messages sent while the agent is working are queued and sent one per turn.
The input winbar shows the pending count.

`gq` opens the queue as plain text in a floating buffer: every prompt is a
block of text, blocks are separated by `─` lines. Edit, reorder, or delete
blocks like any text, then close the window to apply the result to the
queue. `:w` applies without closing. Prompts that the agent picks up while
the editor is open are not re-queued when it closes (unless you edited
them, in which case your edited version stays queued).

==============================================================================
7. THE PLAN PANEL                                                   *acp-plan*

Agents that plan their work announce the steps and keep their status up to
date as they go. Each update lands in the transcript, where the step in
progress is accented and finished steps are checked off — but it scrolls
away as the turn continues.

`gp` opens the latest plan in a float instead, so it is one keypress away
wherever you are in the conversation. Steps read `○` not started, `◐` in
progress, `✓` done; `q` or `:q` closes the panel.

While a plan is live, the chat winbar carries its step count, e.g. `▤ 2/5`.
The plan is saved with the thread, so it is still there after a restart.

Agents that never send a plan simply have none, and `gp` says so.

==============================================================================
8. SUBAGENTS                                                   *acp-subagents*

Agents delegate parts of a job to subagents that work on their own and
report back. ACP has no first-class notion of one, so they arrive as
ordinary tool calls; acp.nvim recognises them by title (|acp-options|
`subagent_patterns`, matching Claude Code's `Task` and the usual naming by
default).

A recognised spawn gets the `◇` icon in the transcript instead of the
generic tool glyph, and joins the thread's subagent list.

`gs` opens that list in a float — one row per subagent with its status
(`○` queued, `◐` running, `✓` done, `✗` failed) and how long it ran. The
rows are a snapshot, so reopen it to re-read the clock; `q` or `:q` closes
it. While any subagent is still running, the chat winbar shows the count as
`◇ 2`.

The list covers the current run of the thread only (the transcript is the
durable record): it survives an idle agent process being stopped and
revived, but not a restart of Neovim.

If your agent names its delegation tool something else, add a pattern: >lua

  require("acp").setup({
    subagent_patterns = { "^Task%f[%W]", "^Delegate" },
  })
<

9. FOLLOW MODE                                                    *acp-follow*

With follow on, the code area jumps to whatever file and line the agent
reports touching, so you watch the work happen instead of chasing it.

By default the edits land in the first code window of the thread's tab,
which is rarely what you want once you have split it. `<leader>cf`
(|:AcpFollow|) marks the window you run it in as the target: from then on
every reveal goes there and the rest of your layout is left alone. Point it
at a scratch window and the agent works in that one while you read your own
file beside it.

The marked window says so in its winbar (`⟳ following claude`), and gets its
own winbar back when unmarked. Only one window per tab can be marked;
marking another moves the mark.

`<leader>cf` also turns follow on, and running it again in the marked window
turns it off. `gf` in the chat toggles follow without touching the mark — a
marked window that is paused reads `⟳ follow paused (gf)`.

Which window is marked is saved with the thread's layout, and whether follow
is on is saved with the thread, so both survive reopening a thread and
restarting Neovim. `ui.follow` (|acp-options|) sets the default for threads
that have never been toggled.

Following only happens while you are looking at that thread's tab; a
background thread never yanks your windows around.

10. OPTIONS                                                      *acp-options*

Defaults: >lua

  require("acp").setup({
    -- ACP agents available for threads. Keys are agent names shown in the
    -- picker; `cmd` spawns an ACP server on stdio; `icon` is shown in the
    -- sidebar. Entries may also set env = { KEY = "value" }.
    agents = {
      claude = {
        cmd = { "npx", "-y", "@agentclientprotocol/claude-agent-acp" },
        icon = "✳",
      },
      codex = {
        cmd = { "npx", "-y", "@agentclientprotocol/codex-acp" },
        icon = "⬡",
      },
      gemini = {
        cmd = { "npx", "-y", "@google/gemini-cli", "--experimental-acp" },
        icon = "◆",
      },
    },
    -- Agent used when only one is configured or none is picked.
    default_agent = "claude",

    -- MCP servers forwarded to every agent session (ACP session/new
    -- mcpServers). Stdio entries:
    -- { name = "...", command = "...", args = {},
    --   env = { { name = "K", value = "V" } } }
    mcp_servers = {},

    -- Start the agent session as soon as a thread is opened (instead of
    -- on the first message).
    autostart = true,

    -- Tool calls whose title matches one of these Lua patterns are
    -- treated as subagent spawns, see |acp-subagents|.
    subagent_patterns = {
      "^Task%f[%W]", "^Agent%f[%W]", "^Explore%f[%W]", "[Ss]ubagent",
    },

    -- Kill the process of a thread idle this long (seconds). Only applies
    -- to agents that support session/load; others are kept alive.
    idle_timeout = 900,

    ui = {
      sidebar_width = 30,
      chat_width = 64,
      input_height = 5,
      -- Height of the details panel docked under the sidebar. Unset, it
      -- matches the prompt window across the way; 0 hides the panel.
      details_height = nil,
      -- Hide the native tabline (sets 'showtabline' to 0).
      hide_tabline = true,
      -- One statusline at the bottom of the screen instead of one per
      -- window (sets 'laststatus' to 3). The plugin's windows carry a
      -- title bar, so a statusline each is noise.
      global_statusline = true,
      -- Window focused after opening/switching a thread: "keep" stays in
      -- the same kind of window you came from; "input" | "code" |
      -- "sidebar" force one.
      focus_on_open = "keep",
      show_thinking = true,      -- render agent thought chunks (dimmed)
      show_diffs = true,         -- render diffs from tool-call content
      -- Lines of terminal output kept inline under a tool call (its
      -- tail). Diffs are never truncated: expanding a tool call shows
      -- the whole change. <S-CR> lifts this too.
      terminal_max_lines = 24,
      diff_context = 3,          -- context lines around each diff hunk
      show_result_meta = true,   -- "── done · 12s" line after each turn
      -- Rename threads from the agent's session title; manual renames
      -- always win.
      auto_title = true,
      -- Follow the agent: jump the code window to tool-call locations as
      -- it works. Default for new threads; toggle per thread with `gf`,
      -- and pick the target window with <leader>cf (|acp-follow|).
      follow = false,
      icons = {
        working = "●",
        attention = "?",
        idle = "✓",
        error = "✗",
        tool = "󰖷",
        -- Per ACP tool kind overrides (read/edit/delete/move/search/
        -- execute/think/fetch), plus "subagent" — a pseudo-kind for
        -- calls that spawn one. Trailing spaces are respected so wide
        -- nerd-font glyphs can bake in the spacing they need.
        tool_kinds = {
          read = " ",
          edit = " ",
        },
        thinking = "✱",
        permission = "⚠",
        user = "❯",
      },
    },

    worktrees = {
      -- Directory (relative to the repo root) where thread worktrees live.
      dir = ".worktrees",
      -- Prefix for branches created for thread worktrees.
      branch_prefix = "agents/",
    },

    persist = {
      enabled = true,
      -- Max transcript entries kept per thread in the state file.
      max_transcript = 2000,
    },

    -- Global keymaps (set a value to false to disable it).
    keymaps = {
      chat = "<leader>cc",
      threads = "<leader>ct",
      selection = "<leader>cs",  -- (visual) attach selection as a chip
      diagnostic = "<leader>cd", -- attach diagnostic under the cursor
      follow = "<leader>cf",     -- follow the agent in this window
    },

    -- vim.notify when a background thread needs attention / finishes.
    notify = true,
  })
<

11. STATUSLINE                                                *acp-statusline*

`require("acp").statusline()` returns a compact summary such as `●2 ?1`
(two threads working, one needing attention), or an empty string when there
are no threads. Example for a custom statusline: >lua

  vim.o.statusline = "%f %= %{v:lua.require'acp'.statusline()} "
<
==============================================================================
12. HIGHLIGHTS                                                *acp-highlights*

All groups are defined with `default = true` — links, except the title chip,
which is derived from the colourscheme — and can be overridden:

  AcpSidebarHint      sidebar hints            -> Comment
  AcpSidebarGroup     workspace group headers  -> Directory
  AcpStatusWorking    working status           -> DiagnosticWarn
  AcpStatusAttention  needs-you status         -> DiagnosticError
  AcpStatusIdle       done status              -> DiagnosticOk
  AcpStatusError      failed status            -> ErrorMsg
  AcpChatUser         user turn header         -> Statement
  AcpChatAgent        agent turn header        -> Constant
  AcpChatTool         tool call title          -> Function
  AcpChatThinking     thought chunks           -> Comment
  AcpChatMeta         meta / plan lines        -> Comment
  AcpChatError        error entries            -> DiagnosticError
  AcpChatPermission   permission prompts       -> DiagnosticWarn
  AcpDiffAdd          added diff lines         -> DiffAdd
  AcpDiffDelete       removed diff lines       -> DiffDelete
  AcpDiffAddText      changed span of a + line -> DiffText
  AcpDiffDeleteText   changed span of a - line -> DiffText
  AcpDiffSep          ⋯ hunk gap markers       -> NonText
  AcpPlanActive       in-progress plan step    -> Title
  AcpChip             context chips            -> Special
  AcpWinbarDetail     detail next to a title   -> Comment
  AcpWinbarTitle      window title chip        -> Title on the Pmenu fill
